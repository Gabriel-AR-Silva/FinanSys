# Domain — Software & Engineering

Antes de recomendar solução:
- identificar stack real
- versão instalada
- ambiente
- erro observado
- comportamento esperado
- restrições
- compatibilidade

Ordem de fonte:
1. documentação oficial da versão aplicável
2. changelog / migration guide / especificação
3. código-fonte e testes
4. issues e PRs de mantenedores
5. artigos/tutoriais
6. fóruns e comunidades como pistas

Separar sintoma de causa.

Nunca assumir que documentação de versão nova vale para versão antiga.

Para dependências externas, avaliar:
- manutenção
- licença
- segurança
- compatibilidade
- reversibilidade
- custo
- impacto em testes e arquitetura
